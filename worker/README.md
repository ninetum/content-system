# worker รับงานตัดคลิป

ตัวเชื่อมระหว่าง **เว็บ (สั่งงาน)** กับ **เครื่องคุณ (ตัดจริง)**

```
เว็บบน Vercel                 Supabase                  เครื่องคุณ
 หน้าโรงตัดคลิป  ──เขียน──▶  ตาราง edit_jobs  ◀──อ่าน──  worker ตัวนี้
                                    ▲                        │
                                    │                   สั่ง agent ตัดด้วย ii23 edit kit
                                    │                        │
 แกลลอรี่/หน้าเว็บ  ◀──────────  Storage  ◀──อัปไฟล์──────────┘
```

## ทำไมต้องรันบนเครื่อง ไม่ใช่บนคลาวด์

งานตัดวิดีโอต้องใช้ ffmpeg, CapCut Desktop, โมเดล VAD (~437 MB) และไฟล์ต้นฉบับที่อยู่ในเครื่อง
Edge Function มีแรม 256 MB และตัดจบใน ~400 วินาที ส่วน Vercel เป็น serverless ไม่มีดิสก์ถาวร
— ทั้งคู่รันงานนี้ไม่ได้ ไม่ว่าจะเขียนโค้ดดีแค่ไหน

## ติดตั้ง

ใช้ Python 3.9+ ที่มากับเครื่อง **ไม่ต้อง pip install อะไรเลย** (ใช้ไลบรารีมาตรฐานล้วน)

```bash
cp worker/.env.example worker/.env
# เปิดแก้ worker/.env เติม SUPABASE_URL, SERVICE_ROLE_KEY และ KIT_DIR
```

สร้างที่เก็บไฟล์ผลลัพธ์: Supabase → **Storage** → New bucket → ชื่อ `edits` → ติ๊ก **Public bucket**

## ใช้งาน

```bash
python3 worker/edit_worker.py --dry-run   # ดูก่อนว่าคำสั่งที่จะส่งให้ agent หน้าตาเป็นยังไง
python3 worker/edit_worker.py --once      # เคลียร์งานที่ค้างรอบเดียว
python3 worker/edit_worker.py             # ค้างไว้ รอรับงานเรื่อย ๆ
```

## ขั้นตอนที่ worker ทำให้

1. ถามคิวทุก 20 วินาที หางานสถานะ **รอเริ่มงาน**
2. **จองงาน** แบบกันชนกัน (อัปเดตเฉพาะแถวที่ยังว่าง — เปิดหลายเครื่องพร้อมกันได้ ไม่แย่งงานกัน)
3. ประกอบคำสั่งจากใบสั่งงาน (สัดส่วน ความยาว ตัดเงียบกี่ ms สไตล์ซับ โทนเพลง ทรานซิชัน)
4. เรียก agent ให้ทำงานในโฟลเดอร์ kit ตามลำดับสกิล:
   `analyze` → `clean-cut` → `transcribe` → `find-assets` → `capcut` → `qc_edit`
5. หาไฟล์วิดีโอที่เพิ่งเกิดใหม่ใต้ `output/` ของ kit
6. อัปขึ้น Supabase Storage → เขียน `result_url` กลับเข้าใบสั่งงาน → สถานะเป็น **รอตรวจ**
7. เพิ่มไฟล์เข้าแกลลอรี่ให้เลย จะได้แนบกับคอนเทนต์แล้วเข้าคิวโพสต์ต่อได้ทันที

ล้มเหลวเมื่อไหร่ สถานะจะเป็น **ตัดไม่สำเร็จ** พร้อมข้อความ error และ log ท้าย ๆ เก็บไว้ในฐานข้อมูล
เปิดดูได้จากหน้าเว็บ ไม่ต้องมานั่งไล่ terminal

## ให้รันเองตอนเปิดเครื่อง (ไม่บังคับ)

**macOS** — สร้าง `~/Library/LaunchAgents/dev.ii23.editworker.plist` ชี้ไปที่สคริปต์นี้
แล้ว `launchctl load` ครั้งเดียว

**Windows** — Task Scheduler → Create Task → Trigger: At log on →
Action: `python.exe C:\path\to\worker\edit_worker.py`

## ความปลอดภัย

`worker/.env` มี **service_role key** ซึ่งข้ามทุก RLS — ไฟล์นี้อยู่บนเครื่องคุณเท่านั้น
`.gitignore` กันไว้แล้ว **อย่าเอาขึ้น repo และอย่าส่งให้ใครทางแชท**
