# ระบบโพสต์อัตโนมัติ + ปักลิงก์ในคอมเมนต์แรก

เอกสารนี้คือขั้นตอนเปิดใช้ "ตั้งเวลาแล้วระบบยิงเอง" ซึ่งเป็นส่วนสุดท้ายที่ทำให้
ระบบทำงานได้โดยไม่ต้องมีคนนั่งกดโพสต์

---

## ภาพรวม

```
pg_cron (ในฐานข้อมูล)  ──ทุก 5 นาที──▶  publish-post (mode: due)
                                              │
                                              ├─ หาคอนเทนต์ที่ status=scheduled และถึงเวลาแล้ว
                                              ├─ เช็กกติกาของช่อง (เว้นกี่นาที / วันละกี่โพสต์)
                                              ├─ โพสต์ขึ้นเพจ (ไม่มีลิงก์ในโพสต์หลัก)
                                              └─ ปักลิงก์ติดตามผลในคอมเมนต์แรกทันที
```

**ทำไมต้องแยกลิงก์ไปคอมเมนต์:** Facebook ลดการมองเห็นโพสต์ที่พาคนออกนอกแพลตฟอร์ม
โพสต์หลักจึงควรเป็นเนื้อหาล้วน แล้วค่อยปักลิงก์ในคอมเมนต์แรก — ระบบทำขั้นนี้ให้อัตโนมัติ

---

## 1. กติกาของแต่ละช่อง

ตั้งที่หน้า **เพจ & ช่อง → แก้ไข** มี 4 ค่า:

| ค่า | ค่าเริ่มต้น | ทำไมต้องมี |
|---|---|---|
| โพสต์ได้สูงสุด/วัน | 4 | กันยิงถี่จนเพจดูเหมือนสแปม |
| เว้นขั้นต่ำ (นาที) | 90 | กัน Facebook มองว่าพฤติกรรมผิดปกติ |
| กันโพสต์สินค้าซ้ำ (วัน) | 21 | กันเอาสินค้าเดิมมาวนซ้ำเร็วเกิน |
| ช่วงเวลาโพสต์ | 7,12,18,21 | ชั่วโมงที่จะปล่อย (เวลาไทย) |

สองค่าแรกบังคับใช้จริงในฝั่งเซิร์ฟเวอร์ — ถ้าเกินโควตา ระบบจะข้ามไปรอบถัดไปและ
บันทึกเหตุผลไว้ใน `publish_results` ไม่ได้เงียบหาย

---

## 2. ตั้งตัวจับเวลา (ทำครั้งเดียว)

เปิด **Supabase → SQL Editor** แล้ววางทั้งก้อน — **แทน `<SERVICE_ROLE_KEY>` ด้วยคีย์จริงของคุณ**
(หาได้ที่ Project Settings → API → `service_role` · อย่าส่งคีย์นี้ให้ใคร รวมถึงในแชท)

```sql
-- เก็บคีย์ไว้ใน vault แทนการฝังในตัว job (ปลอดภัยกว่า)
select vault.create_secret(
  '<SERVICE_ROLE_KEY>',
  'service_role_key',
  'ใช้ให้ตัวจับเวลาเรียก Edge Function'
);

-- ทุก 5 นาที ไปดูว่ามีคอนเทนต์ถึงคิวหรือยัง
select cron.schedule(
  'publish-due',
  '*/5 * * * *',
  $$
  select net.http_post(
    url := 'https://oxfonqvrquqmazzhmlnf.supabase.co/functions/v1/publish-post',
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'Authorization', 'Bearer ' ||
        (select decrypted_secret from vault.decrypted_secrets where name = 'service_role_key')
    ),
    body := '{"mode":"due"}'::jsonb
  );
  $$
);
```

ตรวจว่าตั้งสำเร็จ:

```sql
select jobname, schedule, active from cron.job;
```

ดูผลการยิงล่าสุด:

```sql
select status_code, left(content, 200) as body, created
from net._http_response order by created desc limit 5;
```

### หยุด / แก้ตัวจับเวลา

```sql
select cron.unschedule('publish-due');
```

## 3. ข้อควรรู้ก่อนเปิดใช้จริง

**ต้องเป็นเพจ ไม่ใช่โปรไฟล์ส่วนตัว** — Meta ปิดการโพสต์ลงโปรไฟล์ผ่าน API ตั้งแต่ปี 2018
และต้องผูก Page Access Token ไว้ในตาราง `channel_credentials` แล้ว (ดู `docs/META-API.md`)

**โปรเจกต์ฟรีถูกพักเมื่อไม่ได้ใช้งาน** — Supabase free tier พักโปรเจกต์ที่เงียบราว 1 สัปดาห์
พักเมื่อไหร่ตัวจับเวลาก็หยุดด้วย แต่ถ้า cron ยิงทุก 5 นาทีอยู่แล้ว โปรเจกต์จะไม่เงียบ
จึงไม่ถูกพัก — เปิด cron ไว้ก็แก้ปัญหานี้ไปในตัว

**ระบบ auto-post พังเงียบได้** — สาเหตุที่เจอบ่อยเรียงตามความถี่:
1. Page token หมดอายุหรือถูกเพิกถอน
2. โดน rate limit เพราะยิงถี่เกิน
3. Facebook บล็อกเนื้อหาที่ซ้ำกับโพสต์เก่า

ทุกครั้งที่ล้มเหลวระบบบันทึกเหตุผลลง `publish_results.error` เสมอ
ควรเปิดดูสัปดาห์ละครั้ง:

```sql
select c.title, p.platform, p.error, p.created_at
from publish_results p join contents c on c.id = p.content_id
where p.ok = false order by p.created_at desc limit 20;
```

**คอมเมนต์ล้มเหลวไม่ถือว่าโพสต์ล้มเหลว** — ถ้าโพสต์ขึ้นแล้วแต่ปักคอมเมนต์ไม่สำเร็จ
ระบบยังนับว่าโพสต์สำเร็จ แต่เก็บเหตุผลไว้ใน `publish_results.comment_error`
จะได้ไปปักเองทีหลังได้ ไม่ใช่โพสต์ซ้ำทั้งอัน

## 4. ส่วนที่ยังต้องทำเอง (พูดตรง ๆ)

- **เขียนแคปชั่นด้วย AI** — ยังไม่มีในระบบ ต้องต่อ API ของผู้ให้บริการ LLM และมีค่าใช้จ่ายต่อครั้ง
- **ตอบคอมเมนต์/แชทอัตโนมัติ** — ต้องขอสิทธิ์เพิ่มจาก Meta (`pages_messaging`) และผ่าน App Review
- **ดึงสินค้าจากมาร์เก็ตเพลสอัตโนมัติ** — Shopee ไม่มี public API สำหรับ affiliate
  ต้องนำเข้าผ่าน CSV หรือกรอกเอง
