# สิ่งที่ต้องทำต่อ — เชื่อมแพลตฟอร์ม และต่อกับชุดตัดคลิป

เอกสารนี้ตอบ 2 คำถามที่ถามไว้ตรง ๆ ว่า **อะไรทำได้ อะไรทำไม่ได้ และต้องใช้อะไรบ้าง**

---

## 1. เชื่อม Facebook / Instagram / TikTok ให้โพสต์อัตโนมัติ

### ทำได้ไหม — ได้ แต่ไม่ใช่จากหน้าเว็บตรง ๆ

ทุกแพลตฟอร์มบังคับให้เรียก API ด้วย **access token** ซึ่งห้ามฝังในหน้าเว็บ
(ใครกด View Source ก็เอาไปโพสต์แทนเราได้) ดังนั้นต้องมีตัวกลางฝั่งเซิร์ฟเวอร์
สแต็กนี้ใช้ **Supabase Edge Function** ได้เลย ไม่ต้องเช่าเซิร์ฟเวอร์เพิ่ม

```
เว็บ (หน้านี้)  →  Edge Function (เก็บ token)  →  Graph API / TikTok API  →  โพสต์ขึ้นจริง
```

### สิ่งที่ต้องเตรียมต่อแพลตฟอร์ม

| แพลตฟอร์ม | API ที่ใช้ | เงื่อนไขที่ต้องผ่าน |
|---|---|---|
| **Facebook Page** | Graph API `POST /{page-id}/feed` (ข้อความ/ลิงก์), `/photos`, `/videos` | Meta App + สิทธิ์ `pages_manage_posts`, `pages_read_engagement` ต้องผ่าน App Review |
| **Instagram** | Content Publishing API (`/media` → `/media_publish`) | ต้องเป็นบัญชี Business/Creator ที่ผูกกับเพจ FB + สิทธิ์ `instagram_content_publish` |
| **TikTok** | Content Posting API (Direct Post) | สมัคร TikTok for Developers, ผ่าน audit ของแอป, ผู้ใช้ต้องกด authorize |
| **YouTube** | Data API v3 `videos.insert` | OAuth ของเจ้าของช่อง, มีโควตาอัปโหลดต่อวัน |
| **LINE OA** | Messaging API `broadcast` / `narrowcast` | Channel access token จาก LINE Developers |

### ข้อควรรู้ก่อนลงแรง

- **App Review ของ Meta ใช้เวลา** (หลักวันถึงสัปดาห์) ต้องส่งวิดีโอสาธิตการใช้งาน
- **Token หมดอายุ** — Page token แบบ long-lived อยู่ได้ ~60 วัน ต้องมีงาน refresh
- **IG โพสต์วิดีโอต้องเป็น URL สาธารณะ** ไม่ใช่การอัปโหลดไฟล์ตรง ต้องมีที่เก็บไฟล์ (Supabase Storage ได้)
- ระหว่างที่ยังไม่ผ่านรีวิว ใช้ระบบนี้แบบ **กึ่งอัตโนมัติ** ได้ก่อน: ตั้งคิว → ถึงเวลาแจ้งเตือน → คนกดโพสต์
  (ระบบเก็บเนื้อหา แฮชแท็ก ภาพ และเวลาไว้ให้ครบแล้ว)

### ลำดับที่แนะนำ

1. Facebook Page ก่อน (ง่ายสุด เอกสารครบสุด)
2. ตามด้วย LINE OA (ไม่ต้องรีวิว ได้ token ทันที)
3. Instagram (ต่อยอดจาก Meta App เดิม)
4. TikTok / YouTube ทีหลัง

## 2. ตัดคลิป ทำซับ ตัดช่วงเงียบ ใส่เพลง/SFX/ทรานซิชัน

### ทำได้ และคุณมีเครื่องมืออยู่แล้ว — คือ **ii23 edit kit v2.3.1**

ชุดนั้นทำสิ่งที่ถามมาได้ครบ:

| อยากได้ | สกิลใน kit ที่ทำ |
|---|---|
| ตัดช่วงเงียบ / คำติดขัด / เทคที่พูดใหม่ | `ii23-clean-cut` (Silero VAD + ตัวแบ่งคำไทย กันตัดกลางคำ) |
| ทำซับไทย (และ 2 ภาษา, คาราโอเกะ, ปรับสี/ขอบ/เงา) | `ii23-transcribe` + `ii23-capcut` |
| หาเพลง / SFX / B-roll ที่ใช้เชิงพาณิชย์ได้ | `ii23-find-assets` (Mixkit/Coverr + fallback) |
| สติกเกอร์ / เอฟเฟกต์ / ฟิลเตอร์ / ทรานซิชัน | `ii23-capcut` (เขียนลง CapCut Desktop project โดยตรง) |
| ลบพื้นหลัง | `ii23-cutout` |
| ตรวจก่อนส่งงาน | `ii23-capcut/scripts/qc_edit.py` |

### แต่ **เอาขึ้น Vercel ไม่ได้** — และไม่ควรพยายาม

เหตุผลตรง ๆ:

1. **ต้องใช้ CapCut Desktop ที่ติดตั้งในเครื่อง** — kit เขียนไฟล์ project ลงโฟลเดอร์ CapCut ของเครื่องคุณ
   บนคลาวด์ไม่มีโปรแกรมนี้
2. **Vercel เป็น serverless** — ฟังก์ชันมีเพดานเวลาทำงานและไม่มีดิสก์ถาวร
   งานเรนเดอร์วิดีโอกินเวลาเป็นนาทีถึงชั่วโมงและกินพื้นที่หลาย GB
3. **โมเดลที่ kit ใช้หนัก** (Silero VAD ~437 MB, โมเดลลบพื้นหลัง ~168 MB) เกินขนาด bundle ที่ serverless รับได้
4. **ไฟล์วิดีโอต้นฉบับอยู่ในเครื่องคุณ** — อัปโหลดขึ้นคลาวด์ทุกคลิปคือค่าใช้จ่ายและเวลาที่ไม่จำเป็น
5. **เรื่องลิขสิทธิ์** — kit เป็นสินค้าที่ซื้อมาใช้ (มี license key ผูกเครื่อง) การเอาซอร์สทั้งชุด
   ขึ้น repo สาธารณะ = การแจกจ่ายต่อ ซึ่งผิดเงื่อนไขการขาย
   **โปรเจกต์นี้จึงใส่ `ii23-edit-kit*/` ไว้ใน `.gitignore` แล้ว**

### วิธีที่ใช้ได้จริง: เว็บสั่งงาน + เครื่องคุณเป็นโรงตัด

```
[เว็บบน Vercel]                       [เครื่อง Mac/PC ของคุณ]
 หน้า "โรงตัดคลิป"                     ii23 edit kit + CapCut + ffmpeg
   ↓ กรอกโจทย์ (สัดส่วน/ความยาว/ซับ/เพลง)
   ↓ กด "สร้างคำสั่งสำหรับ agent"
   ↓ คัดลอก  ───────────────────────→  วางในหน้าต่าง Claude Code / Codex
                                          ↓ agent รันสกิลของ kit
                                          ↓ ได้คลิปตัดเสร็จ + ซับ + เพลง
   ← อัปโหลดไฟล์ผลลัพธ์เข้าแกลลอรี่ ←────┘
   → ผูกกับคอนเทนต์ → เข้าคิว → โพสต์
```

**วันนี้ใช้ได้เลย** — หน้า "โรงตัดคลิป" สร้างคำสั่งภาษาไทยที่อ้างสกิลของ kit ให้ครบทุกขั้นแล้ว
รวมถึงกฎสำคัญ เช่น ให้รัน `analyze_context.py` ก่อนตัดสินใจตัด และห้ามเดาถ้าไม่แน่ใจ

### ถ้าอยากให้อัตโนมัติเต็มขั้น (เฟสถัดไป)

ทำ **worker เล็ก ๆ บนเครื่องคุณ** ที่คอยดูตาราง `edit_jobs` ใน Supabase:

1. worker poll ตาราง `edit_jobs` ที่ `status = 'รอเริ่มงาน'`
2. เจองาน → ประกอบคำสั่งแบบเดียวกับที่หน้าเว็บสร้าง → เรียก agent รันสกิลของ kit
3. ตัดเสร็จ → อัปไฟล์ขึ้น Supabase Storage → เขียนกลับที่ `result_url` + `status = 'เสร็จแล้ว'`
4. เว็บเห็นสถานะเปลี่ยนเอง ไม่ต้องคัดลอกคำสั่งด้วยมือ

ตาราง `edit_jobs` และคอลัมน์ `result_url` มีอยู่ใน `supabase/schema.sql` เรียบร้อยแล้ว
เหลือแค่เขียนตัว worker (สคริปต์ Python สั้น ๆ รันบนเครื่องคุณ) เมื่อพร้อม

## 3. สิ่งที่ควรทำเพิ่มในเว็บเอง (เรียงตามความคุ้ม)

1. **ระบบล็อกอิน** (Supabase Auth) — จำเป็นก่อนให้ทีมหลายคนใช้ เพราะ RLS ตั้งไว้ที่ `authenticated` แล้ว
2. **อัปโหลดไฟล์เข้า Supabase Storage** — ตอนนี้แกลลอรี่รับเป็น URL ต้องมีที่ฝากไฟล์เอง
3. **ดึงยอดวิวอัตโนมัติ** — Graph API Insights / TikTok Analytics มาเติมตาราง `content_stats` แทนการกรอกมือ
4. **แจ้งเตือนผ่าน LINE** เมื่อมีคอนเทนต์รออนุมัติหรือถึงเวลาโพสต์
