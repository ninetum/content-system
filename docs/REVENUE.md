# วัดคอนเทนต์เป็น "เงิน" ไม่ใช่แค่ยอดวิว

ยอดวิวเยอะแต่ขายไม่ได้ก็มี เอกสารนี้อธิบายวิธีทำให้ระบบตอบได้ว่า
**โพสต์ไหนทำเงินให้เท่าไหร่** และควรทำคอนเทนต์แบบไหนต่อ

---

## รองรับ 2 โมเดลรายได้

| โมเดล | รายได้คืออะไร | ใช้กับ |
|---|---|---|
| **affiliate** | คอมมิชชั่น (% หรือคงที่ต่อออเดอร์) | Shopee / Lazada / TikTok Shop |
| **ขายเอง** | ราคาขาย − ต้นทุน | ตั๋วทัวร์ สินค้าของเราเอง |

เลือกตอนเพิ่มสินค้า ระบบจะสลับช่องกรอกและวิธีคิดเงินให้เอง
ระบบรวมสองอย่างนี้เป็น "รายได้จริง" ก้อนเดียวในรายงาน

## ⚠️ คอม affiliate ถูกยกเลิกได้ — ระบบจึงแยกสถานะ

ลูกค้าคืนของ = คอมหาย ถ้านับรวมตั้งแต่วันสั่ง คุณจะดีใจกับเงินที่ยังไม่ได้จริง

| สถานะ | นับเป็นรายได้ไหม |
|---|---|
| ⏳ รอยืนยัน | **ไม่นับ** — โชว์แยกไว้ให้เห็นว่ามีอยู่ |
| 👍 ยืนยันแล้ว | นับ |
| ✅ จ่ายแล้ว | นับ |
| ⛔ ยกเลิก | ไม่นับ |

บันทึกออร์เดอร์ตอนเห็นในแอป Shopee ตั้งเป็น "รอยืนยัน" ไว้ก่อน
พอพ้นระยะคืนของแล้วค่อยกลับมาเปลี่ยนเป็น "ยืนยันแล้ว" ตัวเลขรายได้จะขยับเอง

## หน้ารวมลิงก์ (Link-in-bio)

Facebook กดลิงก์ในโพสต์ลำบาก และการแปะลิงก์นอกในโพสต์มักโดนลดการมองเห็น
ทางที่ใช้กันคือใส่ลิงก์เดียวใน bio แล้วรวมสินค้าไว้หน้านั้น

เปิดที่ `bio.html` (เช่น `เว็บคุณ/bio`) — ติ๊ก "โชว์ในหน้า link-in-bio" ที่สินค้า
แล้วกด **"เตรียมลิงก์หน้า bio"** ครั้งเดียว

ได้ของแถมที่ Shopee ไม่เคยบอกคุณ: **รู้ว่าคนกดสินค้าตัวไหนมากที่สุดในหน้า bio**

ทุกลิงก์ติด `rel="sponsored"` ให้อัตโนมัติตามแนวปฏิบัติของ affiliate

## วงจรที่ทำให้วัดได้

```
เพิ่มสินค้า (ใส่ลิงก์ affiliate + % คอม)
      ↓
ผูกสินค้าเข้ากับคอนเทนต์ตอนเขียนโพสต์
      ↓
กดสร้าง "ลิงก์ติดตามผล" — ได้ลิงก์แยกรายช่อง
      ↓
แปะลิงก์นั้นในโพสต์แทนลิงก์ตรง
      ↓
มีคนกด → ระบบนับคลิก + รู้ว่ามาจากช่องไหน
      ↓
ปิดการขายได้ → บันทึกยอดขาย ผูกกับคอนเทนต์นั้น
      ↓
รายงานบอกเอง: คอนเทนต์ไหนทำเงิน / สินค้าไหนขายดี / คอนเทนต์ประเภทไหนคุ้ม
```

## ติดตั้งลิงก์ติดตามผล

```bash
supabase functions deploy r --no-verify-jwt
```

> `--no-verify-jwt` **จำเป็น** เพราะคนทั่วไปที่กดลิงก์ในโพสต์ไม่ได้ล็อกอิน
> ถ้าลืมใส่ ลิงก์จะขึ้น 401 ทั้งหมด

ตั้งหน้าสำรองเผื่อลิงก์ถูกลบ (ไม่บังคับ):

```bash
supabase secrets set FALLBACK_URL=https://หน้าแรกของร้านคุณ
```

ลิงก์ที่ได้จะหน้าตาแบบนี้:

```
https://<project>.supabase.co/functions/v1/r/a7xk2p
```

### อยากได้ลิงก์สั้นสวย ๆ (ไม่บังคับ)

ผูกโดเมนของคุณเข้ากับ Vercel แล้วเพิ่ม rewrite ใน `vercel.json`:

```json
{
  "rewrites": [
    { "source": "/r/:code", "destination": "https://<project>.supabase.co/functions/v1/r/:code" }
  ]
}
```

จะได้ `ร้านคุณ.com/r/a7xk2p` ซึ่งดูน่ากดกว่ามาก

## ระบบนับอะไรให้บ้าง

| ตัวเลข | ความหมาย | ใช้ตัดสินใจอะไร |
|---|---|---|
| **รายได้** | คอมที่ยืนยันแล้ว (+ กำไรจากของที่ขายเอง) | โพสต์ไหนควรทำซ้ำ / ยิงแอดต่อ |
| **รอยืนยัน** | คอมที่ยังถูกยกเลิกได้ | เผื่อใจไว้ อย่าเพิ่งนับเป็นเงิน |
| **EPC** | รายได้ ÷ คลิก | **ตัวชี้ขาดของสายนายหน้า** — สินค้าไหนควรดันต่อ |
| **กำไรสุทธิ** | รายได้ − ค่าแอด | ยิงแอดแล้วคุ้มไหม |
| **คลิก** | จำนวนคนกดลิงก์ | คอนเทนต์ชวนให้กดพอไหม |
| **รายได้ต่อ 1,000 วิว (RPM)** | รายได้ ÷ ยอดวิว × 1,000 | **ตัวชี้ขาด** — คลิปล้านวิวที่ RPM ต่ำ สู้คลิปแสนวิวที่ RPM สูงไม่ได้ |
| **ROAS** | รายได้ ÷ ค่าแอด | ต่ำกว่า 1 คือจ่ายแอดแล้วขาดทุน |
| **CVR** | ออร์เดอร์ ÷ คลิก | คนกดเยอะแต่ไม่ซื้อ = ปัญหาอยู่ที่หน้าสินค้า ไม่ใช่คอนเทนต์ |

## วิธีอ่านตัวเลขให้ได้เงินเพิ่ม

**คลิกเยอะ แต่ขายไม่ได้** → ปัญหาไม่ได้อยู่ที่คอนเทนต์ คอนเทนต์ทำงานแล้ว (คนกด)
ให้ไปแก้หน้าสินค้า ราคา หรือความเร็วในการตอบแชทแทน

**วิวเยอะ แต่คลิกน้อย** → คอนเทนต์สนุกแต่ไม่ได้ชวนให้ทำอะไรต่อ
ลองย้าย CTA ขึ้นมาให้เร็วขึ้น และพูดให้ชัดว่ากดไปเจออะไร

**RPM สูงแต่วิวน้อย** → นี่คือเหมืองทอง ทำคอนเทนต์แบบเดิมซ้ำแล้วดันด้วยแอด

**EPC สินค้าตัวหนึ่งสูงกว่าตัวอื่นชัดเจน** → ทำคอนเทนต์ให้ตัวนั้นเพิ่ม อย่าหว่านเท่ากันทุกตัว
คนกด 100 ครั้งได้ 500 บาท ดีกว่าคนกด 1,000 ครั้งได้ 200 บาท

**คอมเยอะแต่ "รอยืนยัน" ค้างนาน** → เช็กว่าสินค้าที่ดันอยู่เป็นหมวดที่คนคืนของบ่อยหรือเปล่า
(เสื้อผ้า รองเท้า คืนบ่อยกว่าของใช้ทั่วไป) ถ้าใช่ ให้ดันหมวดที่คืนน้อยแทน รายได้จะนิ่งกว่า

**ประเภทคอนเทนต์ที่รายได้เป็น 0 ติดกันหลายชิ้น** → ไม่ได้แปลว่าไม่ดี
คอนเทนต์สร้างการรับรู้ก็จำเป็น แต่ต้องรู้ตัวว่ากำลังลงทุนอะไรอยู่ อย่าให้เกิน 30% ของทั้งหมด

## ข้อจำกัดที่ควรรู้

- **ยอดขายยังต้องกรอกเอง** — ถ้าใช้ Shopee/Lazada/เว็บร้านอยู่แล้ว ขั้นต่อไปคือดึงเข้ามาอัตโนมัติ
- **การนับคลิกไม่เก็บ IP** เก็บแค่ที่มา (referer) และชนิดเครื่อง เพื่อไม่ให้ยุ่งกับ PDPA เกินจำเป็น
- **คนกดซ้ำจะนับซ้ำ** ถ้าต้องการนับแบบไม่ซ้ำคน ต้องเพิ่มการเก็บ cookie ซึ่งมีเรื่องขอความยินยอมตามมา
